# 感知 Agent 作业手册（SKILL v0.1）

## 一、取数配方（照此调用，参数按对象与基准日替换）

| 目的 | 工具调用（参数模板） | 说明 |
| --- | --- | --- |
| 设备可信度前置 | `get_device_status(site_id, as_of)` | 先做：设备离线时相关读数要打问号 |
| 土壤墒情 | `get_sensor_readings(site_id, "soil_moisture", as_of-7d, as_of)` | 需要分层时再取 `soil_moisture_30cm` |
| 温度/湿度 | `get_sensor_readings(site_id, "air_temp" / "humidity", as_of-7d, as_of)` | 湿度高 + 叶面湿润时长长 ⇒ 病害风险线索（只陈述现象） |
| 水质（灌溉源） | `get_sensor_readings(site_id, "water_quality", as_of-7d, as_of)` | 关注 EC / pH 的读数与趋势 |
| 叶面湿润时长 | `get_sensor_readings(site_id, "leaf_wetness", as_of-7d, as_of)` | 与湿度互证 |
| 气象 | `get_weather_forecast(site_id, as_of-7d, as_of)` | 实况与预报必须分开标注 |
| 影像 | `get_camera_snapshot(site_id, as_of)` | 只描述可见特征与分布比例 |
| 遥感 | `get_remote_sensing_index(site_id, "ndvi" / "ndwi", as_of-14d, as_of)` | 看趋势与历史同期偏离，不看单日值 |

补充采集轮次：先完成中枢点名要求的通道与时间窗，再按上表补齐常规通道。

## 二、对比口径（按优先级）

1. 对象档案或台账里给出的历史区间/阈值；
2. 工具返回文本中标注的参考区间（注意它是"演示口径"还是"农艺标准"）；
3. 本窗口自身的趋势（首末差、是否连续偏离）；
4. 都没有 → 只给绝对读数，标注"基线未知"。

## 三、报告自检清单（提交前逐条过）

- [ ] 每个通道都写了：状态、关键读数、时间、对比依据；
- [ ] 预报值标了"预报"，实况标了"实况"，没有混写；
- [ ] 未采集/报错/未接入的通道写进"数据质量与缺口"，没有用"正常"填补；
- [ ] 异常现象每条都能指到"通道 + 时间 + 读数/画面"；
- [ ] 没有出现病因、严重度、处置建议之类的越界表述；
- [ ] "待确认"只列问题，不给答案。

## 四、数据质量红旗（出现即单列）

| 现象 | 处理 |
| --- | --- |
| 读数跳变（相邻两日差 > 参考区间的宽度） | 标注可疑，写清跳变前后数值 |
| 超量程 / 负值 / 单位缺失 | 标注"读数可疑，需校准"，不参与趋势判断 |
| 长时间无更新（> 24h 无新值） | 标注"疑似采集链路故障"，与设备状态互证 |
| 通道清单不确定 | 写明"通道清单来自默认假设，未与台账核对" |
| 工具返回未接入/占位文本 | 原样转述为"该通道未接入"，不得推断为正常 |

## 五、常见反例（不要这样做）

- ✗ "土壤墒情偏低，可能是晚疫病" —— 病因判断不属于感知；
- ✗ "各通道未见异常" 而实际有 3 个通道没取到 —— 缺失必须显式；
- ✗ 把"预报有雨"写成"已经下雨"；
- ✗ 用自己的经验给读数编一个"正常范围"。
