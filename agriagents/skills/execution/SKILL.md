# 执行 Agent 作业手册（SKILL v0.1）

## 一、执行前核对清单（逐条打勾，任一不过即停手）

- [ ] 审批记录为"通过"或"演练模式放行"；
- [ ] 工单对象编号 == 本次对象编号；
- [ ] 每条任务的执行机构、动作、参数齐全且无歧义；
- [ ] 时间窗与工单一致（不早、不晚、不压缩）；
- [ ] 前置条件满足（设备在线、人员到位、天气窗口允许）。

## 二、指令配方（参数只能来自工单，下面是字段结构示例）

| 任务 | actuator | command | params（JSON 字符串） |
| --- | --- | --- | --- |
| 定向灌溉 | `irrigation` | `start` / `stop` | `{"duration_min": 20, "zone": "A"}` |
| 阀门开关 | `valve` | `open` / `close` | `{"valve_id": "VALVE-11"}` |
| 变量喷洒 | `spray` | `start` / `stop` | `{"rate_l_per_ha": 150, "tank_l": 200}` |
| 农机调度 | `machine` | `dispatch` | `{"machine_id": "3号植保机", "field": "FIELD-07"}` |
| 机械臂 | `arm` | `pick` / `place` | `{"target": "..."}` |

字段结构只是格式参考；**值必须来自工单**，工单没写就停下来问，不要用经验值补齐。

## 三、执行中与执行后

1. 每条 `.dispatch_command` 之后必须 `.get_execution_status(task_id)` 回读；
2. 失败立即停止后续动作，把"停在哪一条、为什么"写清楚；
3. 同一指令最多重试一次，记录重试次数与原因；
4. 记录与工单的偏差（未做 / 多做 / 参数不同），逐条对应，不写"基本完成"；
5. 演练模式（dry_run）也要走完下发-回读流程，但每条记录都要写明"演练，未实际下发"。

## 四、立即停止并上报的条件

- 参数缺失或与工单冲突；设备离线/故障码与工单前提矛盾；
- 天气窗口不满足（风力 ≥4 级、24h 内 ≥10mm 降水等）；
- 人员未到位或防护不到位；
- 回执异常（任务被拒绝、状态未知、重复回执）；
- 现场情况与工单描述不一致（对象、作物、设备编号对不上）。

## 五、常见错误

- ✗ 把"计划要做"写成"已经做了"；
- ✗ 自行调整用量、时长或顺序；
- ✗ 省略回读，凭下发返回就当成功；
- ✗ 用演练模式的记录冒充实发，或反过来；
- ✗ 越界解释病因或重新规划方案（应上报中枢）。
