# 协调决策中枢作业手册（SKILL v0.1）

## 一、动作速查表（先看安全，再看证据，最后看成本）

| 情形 | 动作 |
| --- | --- |
| 关键通道缺失 / 初筛 unknown / 置信度 low，且严重度可能 ≥ medium | `perceive_more`（点通道 + 时间窗）或 `diagnose_more`（点假设） |
| 严重度 high / critical 且置信度 ≥ medium | `plan_work_order` |
| 严重度 medium 且置信度 high | `plan_work_order`（排期，不紧急） |
| 严重度 low / none，且证据完整、无不可逆风险 | `close`（处置预判给"观察"） |
| 涉及人员/水源/环境风险或不可逆动作 | `plan_work_order`（**不得 close**，交由安检与审批） |
| 补采/补诊断预算耗尽 | 在 `plan_work_order` 与 `close` 之间决断；拿不准选前者 |

## 二、请求写法模板（下游必须能照着执行）

```
要哪个对象：FIELD-07（不要只写"该地块"）
要哪个通道/假设：soil_moisture 10cm 与 30cm 两层；排除传感器漂移
要哪个时间窗：2026-09-12 ~ 2026-09-19（as_of 前 7 天）
验收口径：得到带日期与单位的读数序列，两层趋势一致才算排除漂移
```

## 三、决策自检清单

- [ ] 动作四选一，且与上方速查表一致；
- [ ] 依据引用了具体证据（通道+时间+读数，或诊断的哪条判据）；
- [ ] 没有复述、改写、推翻诊断结论；有疑问时用 `diagnose_more` 追问；
- [ ] 若分派：请求写清了对象、通道/假设、时间窗、验收口径；
- [ ] 处置预判与证据强度匹配；
- [ ] 收口时必须写清"为什么现有证据足够"。

## 四、常见错误

- ✗ 因为"补数据更保险"而无限补采 —— 预算用尽必须决断；
- ✗ 在证据缺失时用"无需处置"收口 —— 缺失不等于正常；
- ✗ 自己给诊断下结论（"这明显是晚疫病"）—— 越界且破坏可审计性；
- ✗ 在存在安全风险信号（如阀门故障 + 施药计划）时跳过安检。

## 五、与下游的接口

- 分派 `perceive_more` → 写 `pending_requests`；分派 `diagnose_more` → 写 `pending_request`；
- 出工单 → 工单规划负责"怎么做"，安全检查负责"能不能做"，人工审批负责"准不准做"；
- 反馈或回滚回来后，基于新事实重新决策，不要沿用上一轮的理由。
